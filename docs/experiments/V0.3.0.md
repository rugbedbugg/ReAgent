# v0.3.0 work queue

Keep the current dependency constraints and toolchain pins. Commit implementation
milestones and reviewed findings with signed commits. Commands and analysis code
belong in Git; large routes, live logs and queue state belong under ignored `data/`.
No release tag until the release results and CI have been reviewed.

## Ordered work

1. **Catalogue baseline and source ranking.** Finish the current hard-24 run,
   then measure moderate-25. Both report every profile from one search pass.
2. **Unclipped pooling.** Run a Retro* control and `mcts,retrostar` on both sets
   with `--max-routes 40`, then repeat both arms with build mode. Equal caps
   keep truncation from masquerading as a search improvement.
3. **Leaf-fraction sweep.** Measure 0.5 and 0.7 on both sets; the build controls
   already supply 0.6. Include an exploratory 0.4 pilot on the first five targets
   of each set. The clipped vectors cannot prove 0.4 is impossible. The pilot is
   not a representative estimate or a sufficient basis for excluding it globally.
4. **Matched total budget controls.** Run Retro* at 1,000 iterations / 3,600
   seconds on both sets, unconstrained and build. Compare with pooled runs at
   500 / 1,800 per algorithm. These match nominal total iteration and clock
   ceilings, not actual time spent or equivalent work per iteration. Report
   elapsed time and timeouts; do not call this an exact equal-runtime comparison.
5. **Review and commit findings.** Compare solve-rate, selected-route quality,
   construction, candidate counts, timeouts and elapsed time. Keep negative
   findings. Do not tune the released defaults on a five-target pilot alone.
6. **Widened agent evaluation (stretch).** Reuse full checkpoint routes on both
   sets, verify Ollama/model availability, and add checkpoint input to the agent
   command. Its current `--hashed-stock` flag is not passed to the backend.
   Numeric-reference checks do not establish factual correctness of rationales;
   assess that separately if making claims about them.
7. **Larger local model (later).** Use the same routes as task 6, and choose the
   model after checking its memory requirements. Measure quality and latency.
8. **Supplier prices (separate release).** Establish a usable data source and
   purchasing units/coverage before replacing the synthetic-accessibility proxy.

The first four tasks expand to 20 serial jobs in [v0.3.0.json](v0.3.0.json).
Tasks 5 onward require review or additional implementation and are recorded as
follow-ups, not automatically launched commands. This is a multi-hour queue;
the complete sweeps can extend well beyond a single session.

## Run or resume

From the repository root:

```sh
uv run --no-sync python -m reagent.eval.queue --plan docs/experiments/v0.3.0.json --dry-run
uv run --no-sync python -m reagent.eval.queue --plan docs/experiments/v0.3.0.json
```

The current Linux run can be adopted without a second writer:

```sh
uv run --no-sync python -m reagent.eval.queue \
  --plan docs/experiments/v0.3.0.json \
  --wait-for-run data/evaluations/hard-retrostar-emol14-2026-09-07/run.json
```

The runner waits for that exact PID and command to exit, then replays or resumes
its checkpoint as the first job. It uses the Python interpreter selected by uv,
starts one search worker at a time, and waits for 4,608 MB of available RAM before
each job. Below 768 MB available during a job, it stops its own child and marks
the queue failed; it never terminates unrelated applications. These are operational
guardrails, not a guarantee that a search cannot exhaust memory between probes.

`data/evaluations/v0.3.0-queue/state.json` records ordered progress, commands,
attempt logs, child PIDs, exit codes and elapsed seconds. An OS lock excludes a
second queue runner. On Linux, restart waits for a surviving recorded child
before it reuses that child's checkpoint. Do not run direct evaluations against
these directories while the queue is active.

Restart with the same command after resolving a failure. Completed jobs replay
their saved routes and validate their fingerprints; pending targets search again.
A changed plan requires a new queue output directory. Checkpoint compatibility
is checked separately by `evaluate`.

Timing includes process startup and scoring. A replay's elapsed time is not a
search benchmark, and retries include abandoned work: retain every attempt log
and mark interrupted comparisons accordingly. The adopted first run's original
log and start time remain under its existing directory.
